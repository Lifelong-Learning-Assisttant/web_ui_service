# ADR: Решение по обработке LaTeX формул

**Дата**: 2025-12-26  
**Статус**: ✅ Принято  
**Автор**: Team

## Контекст

### Проблема
Приложение должно корректно отображать математические формулы в формате LaTeX, которые приходят от AI-агента. Агент может использовать разные форматы LaTeX:
- `$$...$$` - блочные формулы
- `\(...\)` - строчные формулы  
- `\[...\]` - альтернативные блочные формулы

NiceGUI 3.4.1 поддерживает LaTeX через `ui.markdown(extras=['latex'])`, но ожидает строго определенные форматы (`$...$` и `$$...$$`).

### Требования
- ✅ Надежное отображение формул
- ✅ Поддержка разных LaTeX форматов
- ✅ Независимость от конкретного LLM
- ✅ Простота поддержки
- ✅ Красивый UI

## Решение

### Комбинированный подход: Промпт + Парсер

#### 1. Промпт агента (`agent_service/prompts/system_prompt.txt`)

**Цель**: Направить агента использовать правильные форматы с самого начала.

**Инструкция**:
```
- **Форматирование формул для NiceGUI:**
  Используй строго следующие форматы для всех математических формул:
  
  1. **Строчные формулы** (внутри текста): `$...$`
     - Правильно: "Формула $E=mc^2$ важна"
     - Неправильно: "Формула \(E=mc^2\) важна"
  
  2. **Блочные формулы** (отдельной строкой): `$$...$$`
     - Правильно: 
       ```
       $$MSE = \frac{1}{n} \sum_{i=1}^{n} (y_i - \hat{y}_i)^2$$
       ```
     - Неправильно:
       ```
       \[MSE = \frac{1}{n} \sum_{i=1}^{n} (y_i - \hat{y}_i)^2\]
       ```
  
  Важно: Все формулы должны быть в формате `$...$` или `$$...$$`. Не используй `\(...\)` или `\[...\]`!
```

**Плюсы**:
- Агент сразу отправляет правильные форматы
- Меньше работы для парсера
- Чистый код

**Минусы**:
- Зависимость от качества LLM
- Может "забыть" формат в длинных диалогах
- Разные LLM могут интерпретировать промпт по-разному

#### 2. Парсер в UI (`web_ui_service/frontend/web_ui.py`)

**Цель**: Защита от некорректных форматов и поддержка всех возможных вариантов.

**Код**:
```python
async def add_message_to_ui(role: str, content: str, meta: Optional[dict] = None):
    # ... (пропущены другие обработки)
    
    # Обработка текста с формулами LaTeX через NiceGUI markdown
    elif content and ('$' in content or '\\(' in content or '\\[' in content):
        # Используем NiceGUI markdown с поддержкой LaTeX
        # Конвертируем LaTeX форматы в формат markdown2 latex
        import re
        markdown_content = content
        
        # Блочные формулы $$...$$ -> $$...$$
        markdown_content = re.sub(r'\$\$(.*?)\$\$', r'$$\1$$', markdown_content, flags=re.DOTALL)
        # Строчные \(...\) -> $...$
        markdown_content = re.sub(r'\\\\\\((.*?)\\\\\\)', r'$\1$', markdown_content)
        # Строчные \[...\] -> $$...$$
        markdown_content = re.sub(r'\\\\\\[(.*?)\\\\\\]', r'$$\1$$', markdown_content, flags=re.DOTALL)
        
        # Используем ui.markdown с поддержкой LaTeX
        ui.markdown(markdown_content, extras=['latex'])
```

**Поддерживаемые форматы**:
- `$$...$$` → `$$...$$` (блоки остаются)
- `\(...\)` → `$...$` (строчные конвертируются)
- `\[...\]` → `$$...$$` (альтернативные блоки конвертируются)

**Плюсы**:
- ✅ Работает с любым LLM
- ✅ Обрабатывает все форматы
- ✅ Надежная защита
- ✅ Не требует изменений агента

**Минусы**:
- Дополнительная обработка
- Немного сложнее в поддержке

## Почему такой подход?

### Двойная защита (Defense in Depth)

1. **Промпт** → Оптимизация
   - Агент старается использовать правильные форматы
   - Уменьшает нагрузку на парсер
   - Улучшает производительность

2. **Парсер** → Надежность
   - Работает всегда, даже если агент ошибся
   - Поддерживает все форматы
   - Независим от LLM

### Аналогия

Как **пояс и подтяжки**:
- Пояс (промпт) держит штаны в правильном положении
- Подтяжки (парсер) гарантируют, что они не упадут, даже если пояс ослабнет

## Альтернативы

### Вариант 1: Только промпт
❌ **Отклонено**: Слишком рискованно, LLM может ошибиться

### Вариант 2: Только парсер
✅ **Возможно**, но тогда агент может отправлять неоптимальные форматы

### Вариант 3: Изменить NiceGUI
❌ **Отклонено**: Слишком сложно, требует форка

### Вариант 4: Использовать KaTeX вместо MathJax
❌ **Отклонено**: Меньше поддержка конструкций, нужен дополнительный код

## Результаты

### Что работает:
- ✅ Строчные формулы: `$E=mc^2$`
- ✅ Блочные формулы: `$$MSE = \frac{1}{n}$$`
- ✅ Сложные конструкции: `\sum`, `\int`, `\begin{matrix}`
- ✅ Все форматы LaTeX от агента
- ✅ Автоматическая конвертация
- ✅ Красивый UI с темной темой

### Производительность:
- Быстрый рендеринг (MathJax 3.x)
- Кэширование стилей
- Оптимизированный CSS

## Вывод

**Комбинированный подход** (промпт + парсер) — это оптимальное решение, которое:
1. Дает рекомендации агенту
2. Гарантирует работу с любыми форматами
3. Прост в поддержке
4. Надежен в продакшене

Такой подход следует принципу "Доверяй, но проверяй" (Trust but verify).
